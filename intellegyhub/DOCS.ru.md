# Примечания о работе дополнения

При запуске дополнение читает `/data/options.json`, проверяет номера линий GPIO, отклоняет совпадающие линии светодиода и кнопки, запрашивает линию светодиода как выход, устанавливает его в логическое состояние «выключено», считывает состояние кнопки и запускает обработчик событий изменения сигнала.

Обработчик событий кнопки работает вне основного цикла asyncio. После каждого изменения сигнала он ожидает заданный интервал подавления дребезга, считывает окончательное логическое состояние кнопки и отправляет одно событие изменения состояния, если устойчивое значение изменилось.

Фиксированный вход питания Power на GPIO17 также представлен состоянием кнопки. Если включён параметр
`power_button.shutdown_enabled`, нажатие запускает отменяемый таймер удержания.
Если отпустить кнопку раньше времени, заданного параметром `power_button.shutdown_hold_seconds`, ничего не произойдёт;
удержание кнопки в течение заданного времени от `0.1` до `1.5` секунды при необходимости включает
настроенный звуковой сигнал зуммера GPIO18 с фиксированной громкостью 80%, дожидается его завершения и затем отправляет
`POST http://supervisor/host/shutdown` с токеном дополнения `SUPERVISOR_TOKEN`.

`GET /health` возвращает `200 {"status":"ok"}`, когда дополнение готово к работе, и `503`, если запуск или инициализация оборудования завершились ошибкой.

## Локальный просмотр интерфейса в Windows

Веб-интерфейс дополнения можно проверить локально без HAOS, запустив сервер
в режиме эмуляции из корня репозитория:

```powershell
python -m pip install -r requirements-local-ui.txt
$env:INTELLEGY_GPIO_MOCK="1"
$env:INTELLEGY_ADDON_OPTIONS='{"diagnostics":{"carrier_monitoring_poll_interval_seconds":30},"onewire":{"bus1_poll_interval_seconds":30,"bus2_poll_interval_seconds":30}}'
python -m uvicorn addon.app.main:app --host 127.0.0.1 --port 8098 --reload
```

Откройте:

```text
http://127.0.0.1:8098/
```

В этом режиме используются эмулированные данные GPIO/I2C. Он позволяет проверить разметку интерфейса и структуру API,
но не подтверждает работу реального оборудования CM4.

## Диагностика I2C на CM4

На проверенном оборудовании CM4 HAOS предоставляет нужные шины I2C как `/dev/i2c-1` и `/dev/i2c-10`.
Дополнение явно подключает обе шины через `devices` вместе с `/dev/gpiochip0`.

Необходимые метаданные дополнения:

```yaml
devices:
  - /dev/gpiochip0
  - /dev/i2c-1
  - /dev/i2c-10
  - /dev/mem
  - /dev/vcio
```

Пути GPIO и I2C работают при явном указании `devices`, но HAOS монтирует `/sys/class/pwm` внутри дополнений только для чтения.
Поэтому диагностика аппаратного PWM на GPIO18 запускает `pigpiod` и использует `pigpio.hardware_PWM()` через сокет демона.
Для этого требуются `full_access: true`, `gpio: true`, `SYS_RAWIO`, `/dev/mem`, `/dev/vcio` и отключённый режим защиты.

Веб-интерфейс дополнения через Ingress содержит:

- `Devices` — список `/dev/gpio*` и `/dev/i2c*`, доступных внутри контейнера дополнения.
- `Scan I2C-1` — сканирование `/dev/i2c-1`.
- `Scan I2C-10` — сканирование `/dev/i2c-10`, шины VC/левой шины в проверенной конфигурации CM4.

Конфигурация загрузки HAOS должна загружать модуль символьных устройств Linux I2C. В загрузочном разделе создайте:

```text
CONFIG/modules/rpi-i2c.conf
```

с содержимым:

```text
i2c-dev
```

Файл `config.txt` загрузочного раздела должен включать параметры прошивки I2C для CM4, например:

```ini
arm_64bit=1
dtparam=i2c_arm=on

[cm4]
otg_mode=1

[all]
enable_uart=1
dtoverlay=uart3
dtoverlay=uart5
dtparam=i2c1=on
dtparam=i2c_vc=on
dtparam=spi=off
gpio=16=ip,np
gpio=23=ip,np
dtoverlay=gpio-shutdown,gpio_pin=17,active_low=1,gpio_pull=up,debounce=1000
dtoverlay=pwm,pin=18,func=2
dtparam=ant2
dtoverlay=i2c-rtc,pcf85063a,i2c_csi_dsi
```

После изменения загрузочных файлов выполните `ha host reboot` и проверьте:

```sh
hwclock -w
ls -la /dev/i2c*
lsmod | grep -i i2c
hwclock -r
cat /sys/class/rtc/rtc0/hctosys
```
